How do we make slides that aren't strawman?

The gap between "AI-generated deck" and "deck I'd actually present" is content fidelity, visual evidence, and narrative confidence. Here's what a cracked team would build.

Why AI decks feel like strawmen today

Placeholder content syndrome

Slides say "Key Metric: [X%]" or "Customer Name: [TBD]". The user does all the hard work of filling in real data. The AI produced a template, not a deck.

Generic narrative arc

"Problem → Solution → Benefits → Next Steps" — every deck. No customer-specific insight, no surprising data point, no opinion. The story could be about anything.

No visual evidence

Architecture slides show boxes labeled "Service A" → "Service B". Data slides show fake bar charts. No real diagrams, no real screenshots, no real numbers.

No presenter confidence

The user didn't build the story — they described it in one sentence and got 12 slides back. They can't defend slide 7 because they didn't write slide 7.

What a cracked team builds instead

1
Narrative interview, not prompt-and-pray

The agent conducts a structured interview: "Who's in the room? What do they already know? What's the one thing they should remember? What decision do you need from them?" Each answer sharpens the story arc. The user builds the narrative through conversation, not through a single prompt.

UI mechanism: QuestionForm with direction-cards for audience/tone, then an interactive outline editor where the user can reorder, split, merge beats. Each beat shows a one-line summary the user wrote or approved — not AI-generated filler.
2
Content-first slide cards, not layout-first

Before any visual design, each slide shows its content intent as a card: the headline, the supporting point, the evidence type (data, diagram, quote, image), and the speaker note. The user edits the substance before the agent touches layout.

UI mechanism: Slide Planner view — cards in a horizontal strip. Each card shows: beat label, headline, evidence type selector (dropdown: chart / diagram / screenshot / quote / stat / none), key data point input, speaker note textarea. User fills in the substance, agent handles the design.
3
Real visual evidence, generated or attached

When a slide needs an architecture diagram, the agent generates one using Mermaid/SVG — not a placeholder box. When a slide needs a chart, the agent builds it from data the user provides. When a slide needs a screenshot, the user drags it onto the slide card. The system never ships a slide with "[insert image here]".

UI mechanism: Evidence attachment per slide card. For "diagram" type: agent generates inline SVG using Mermaid syntax from the user's description. For "chart" type: agent generates a data-driven chart from user-pasted numbers. For "image" type: drag-drop zone on the slide card. For "stat" type: big-number layout auto-generated.
4
Progressive rendering with live critique

Each slide renders as soon as its content card is complete — the user sees it immediately, not after all 12 are done. The agent runs a self-critique after each slide: "Does this slide earn its place? Is the headline specific enough? Does the evidence support the claim?" Issues surface as inline badges on the slide thumbnail.

UI mechanism: Slide sorter with live thumbnails. Each thumbnail shows a quality badge: green (strong), amber (needs evidence), red (placeholder content detected). Clicking a badge scopes the chat to that slide's issue. The agent can suggest: "Slide 4 says 'significant improvement' — can you give me the actual percentage?"
5
Presenter rehearsal with confidence scoring

Before export, a rehearsal mode shows each slide with its speaker notes. The agent asks: "Can you explain this slide in your own words?" If the user struggles, the slide content is too far from what they actually know — the agent rewrites it closer to what the user said aloud. The user should be able to defend every slide because they co-authored every slide.

UI mechanism: Presenter preview mode. Full-screen slide + speaker notes. "Explain this slide" button that records the user's description and compares it to the slide content. Confidence indicator per slide. Optional: rewrite the slide to match the user's natural phrasing.

The anti-strawman contract

Rules the skill enforces:
1. No slide ships with placeholder text — if the agent doesn't have real content, it asks for it
2. Every data slide must reference a specific number the user provided
3. Every architecture diagram must be generated, not described
4. Every headline must be specific — "40% latency reduction in 6 weeks" not "Significant improvement"
5. Speaker notes are not optional — they're the proof the user can present this
6. The agent pushes back on vague beats: "What specifically happened at the reference customer?"

The core insight: Strawman decks happen because the user delegates content, not just design. The fix isn't better AI generation — it's a workflow where the user authors the substance (through interview + content cards + evidence attachment) and the AI handles the craft (layout, typography, visual hierarchy, theme binding). The user should never see a slide they didn't intellectually build.
